# 10 — 调试视图与计时

## 这一章要解决什么问题

第 09 章结束时画面已经"对"了：高光带随拖拽移动，Gouraud 与逐像素肉眼可分。但"对"之外你还需要两种能力：
画面**错**的时候，看见缓冲里存了什么；画面**慢**的时候，看见时间花在哪一段。这一章交付：`V` 键循环的四种视图、
`--bench N` 的分阶段计时表、读 A/B 帧时间的纪律——**计时数字随机器/构建/运行变，别当精度证据**。引用基于 HEAD `97a1499`（`git log -1 --oneline`）。

## 两种机制的分界：FS 视图与 sink 视图（D23）

视图状态是 `app::ViewMode { Color, Depth, Gray, Normal }`（`src/app/view_mode.h:20`），路由表是
`planView(mode, defaultFS) → ViewPlan{fragmentShader, sink, name}`（`src/app/view_mode.cpp:8-23`）：

| 模式 | FS | 帧末 sink | 机制 |
|---|---|---|---|
| COLOR | defaultFS 原样透传 | Color（恒等） | 正常显示 |
| DEPTH | defaultFS 原样透传 | Depth | 后处理读整张深度缓冲 |
| GRAY | defaultFS 原样透传 | Gray | 后处理读已写好的颜色 |
| NORMAL | **覆写**为 `debugNormalFS` | Color（恒等） | 普通 FS，逐像素判定 |

分界写死在 `src/render/sink.h:18-25`：**能逐像素判定的视图走普通 FS**（法线读本像素插值出来的
`worldNormal`，只有 FS 拿得到）；**需要整张缓冲的视图走 sink**——FS 看不见别的像素的深度/颜色，
硬改成 FS 等于伪造一个不可能的接口。所以 `DebugViewSink::View` 只有 Color/Depth/Gray，**不加 Normal**
（`sink.h:28-30`）；Normal 的 sink 必须恒等，再过后处理会把编码改写掉。枚举值即 `V` 循环顺序
（`main.cpp:404-412` 的 `%4`，`tests/unit/test_view_mode.cpp:199-202` 钉住）；切换状态进终端 `[view]`
行与 HUD 第二行 `VIEW %s`（`main.cpp:232-237`）；sink 在 HUD 文字**之前**应用（`main.cpp:213-217`）。

## 片段 1：阶段计时器——lap 划分时间，覆盖丢掉时间

只用标准库 + `<chrono>`。假渲染循环：4 个输入三角形，第 0 个被"裁"成 3 个子三角形的扇形，
setup/raster 的 lambda 因此被进入 6 次。三种写法各跑一遍（`build/guide-scratch-10/snippet1.cpp`）：

```cpp
#include <chrono>
#include <cstdio>
class Timer {   // 与 src/bench/timer.h 同形
  public:
    using Clock = std::chrono::steady_clock;
    Timer() : m_start(Clock::now()) {}
    double elapsedMs() const {
        return std::chrono::duration<double, std::milli>(Clock::now() - m_start).count();
    }
    double lapMs() {   // 读一次时钟并重启在当下 ⇒ 相邻 lap 首尾相接
        const auto now = Clock::now();
        const double ms = std::chrono::duration<double, std::milli>(now - m_start).count();
        m_start = now;
        return ms;
    }
    Clock::time_point m_start;   // class 默认 private
};
volatile double g_sink = 0.0;
void work(int iters) { double a = 0.0; for (int i = 0; i < iters; ++i) a += 1.0 / (1.0 + i); g_sink = g_sink + a; }
struct Stats { double vs = 0, clip = 0, setup = 0, raster = 0, total = 0; };
enum class Mode { Accumulate, Overwrite, ElapsedNoRestart };
void drawRange(Stats& s, Mode mode) {
    Timer total, stage;
    for (int tri = 0; tri < 4; ++tri) {
        const int subs = (tri == 0) ? 3 : 1;   // 扇形：同一 lambda 多次进入
        work(200000);                          // VS
        s.vs += (mode == Mode::ElapsedNoRestart) ? stage.elapsedMs() : stage.lapMs();
        work(100000);                          // clip
        s.clip += (mode == Mode::ElapsedNoRestart) ? stage.elapsedMs() : stage.lapMs();
        for (int t = 0; t < subs; ++t) {
            work(100000);                      // setup
            const double a = (mode == Mode::ElapsedNoRestart) ? stage.elapsedMs() : stage.lapMs();
            if (mode == Mode::Overwrite) s.setup = a; else s.setup += a;
            work(600000);                      // raster（逐像素循环的替身）
            const double b = (mode == Mode::ElapsedNoRestart) ? stage.elapsedMs() : stage.lapMs();
            if (mode == Mode::Overwrite) s.raster = b; else s.raster += b;
        }
    }
    s.total += total.elapsedMs();
}
int main() {
    const char* names[] = {"accumulate(+=", "overwrite(=)", "elapsed-no-restart"};
    for (int m = 0; m < 3; ++m) {
        Stats s; int draws = 0;   // Ruling 84 防抖：先重复到 total >= 2.0ms 再谈比值
        do { drawRange(s, static_cast<Mode>(m)); ++draws; } while (s.total < 2.0 && draws < 100000);
        const double sum = s.vs + s.clip + s.setup + s.raster;
        std::printf("%-19s draws=%d vs=%.3f clip=%.3f setup=%.3f raster=%.3f | sum=%.3f total=%.3f ratio=%.4f\n",
                    names[m], draws, s.vs, s.clip, s.setup, s.raster, sum, s.total, sum / s.total);
    }
}
```

编译运行：`g++ -std=c++20 -Wall -Wextra -ffp-contract=off snippet1.cpp -o snippet1 && ./snippet1`。
本机实测（g++ 16.1 MSYS2 UCRT64，-O0，单次运行；数字随机器变，**结构**不变）：

```text
accumulate(+=       draws=1 vs=1.562 clip=0.982 setup=1.159 raster=7.181 | sum=10.884 total=10.884 ratio=1.0000
overwrite(=)        draws=1 vs=1.662 clip=0.783 setup=0.193 raster=1.169 | sum=3.808 total=10.661 ratio=0.3572
elapsed-no-restart  draws=1 vs=21.461 clip=22.252 setup=28.706 raster=35.718 | sum=108.137 total=10.531 ratio=10.2688
```

三行各演示一件事：**`+=` 时四段之和 telescoping 成"最后一次 lap − 起点"**，ratio=1.0000——四段*划分*了
draw 的时间；**`=` 覆盖只留下最后一个子三角形的 setup/raster**，前面 5 次进入 lambda 的时间凭空消失，
ratio 掉到 0.3572（生产测试的 0.5 下界会红）；**`elapsedMs()` 不重启**读到累计值，求和远大于 total
（ratio 10.27）——"四段写同一个数"一类糊弄的数学形状。

## 片段 2：视图路由复刻 + 生产探针交叉核对

2a 是自包含复刻（`build/guide-scratch-10/snippet2a.cpp`），shader 用替身指针——**身份即真相**：

```cpp
#include <cmath>
#include <cstdio>
enum class ViewMode { Color, Depth, Gray, Normal };   // 枚举值 = V 循环顺序
enum class SinkView { Color, Depth, Gray };           // 没有 Normal：它是 FS，不是 sink
using FS = bool (*)(int);
bool defaultFS(int) { return true; }   bool debugNormalFS(int) { return true; }
struct ViewPlan { FS fs; SinkView sink; const char* name; };
ViewPlan planView(ViewMode m, FS def) {
    switch (m) {
        case ViewMode::Normal: return {debugNormalFS, SinkView::Color, "NORMAL"};
        case ViewMode::Depth:  return {def, SinkView::Depth, "DEPTH"};
        case ViewMode::Gray:   return {def, SinkView::Gray, "GRAY"};
        case ViewMode::Color:  break;
    }
    return {def, SinkView::Color, "COLOR"};
}
float encodeAnalytic(float v) {   // IEC 61966-2-1，与生产 color.cpp:10-14 同式
    if (v <= 0.0031308f) return 12.92f * v;
    return 1.055f * std::pow(v, 1.0f / 2.4f) - 0.055f;
}
int toByte(float l) { float c = (l < 0.0f) ? 0.0f : ((l > 1.0f) ? 1.0f : l); return static_cast<int>(std::lround(encodeAnalytic(c) * 255.0f)); }
int main() {
    for (int m = 0; m < 4; ++m) {
        const ViewPlan p = planView(static_cast<ViewMode>(m), defaultFS);
        std::printf("%-6s fs=%s sink=%d\n", p.name,
                    p.fs == debugNormalFS ? "debugNormalFS(override)" : "defaultFS(passthrough)",
                    static_cast<int>(p.sink));
    }
    std::printf("depth  d=0.25 -> g=0.75 -> byte %d\n", toByte(0.75f));
    std::printf("normal N=(0,0,1) -> bytes (%d,%d,%d)\n", toByte(0.5f), toByte(0.5f), toByte(1.0f));
    std::printf("gray   linear(1,0,0) -> g=0.2126 -> byte %d\n", toByte(0.2126f));
    std::printf("no-encode 0.5 -> %d ; double-encode -> %d\n",
                static_cast<int>(std::lround(0.5f * 255.0f)), toByte(encodeAnalytic(0.5f)));
}
```

## 指回本仓库：四个阶段的边界在哪几行

生产计时在 `BackendA::drawRange`（`src/render/render_backend.cpp`），四段共用**一只**秒表 `stage`
（:52），另有一只 `total`（:41）只读一次 `elapsedMs()` 写 `msTotal`（:160）：

| 段 | 覆盖的工作 | lap 落点 |
|---|---|---|
| msVertex | 3 次顶点着色器调用 | `render_backend.cpp:139` |
| msClip | `clipPolygonToFrustum` | `render_backend.cpp:146`，在 `n==0` 的 continue **之前** |
| msSetup | 视口投影 + `setupTriangle`（含被拒绝的三角形） | `render_backend.cpp:67`，rasterOne 内 |
| msRaster | 逐像素循环：覆盖/插值/深度/FS/编码/写回 | `render_backend.cpp:124`，rasterOne 末尾 |

两条边界理由在代码注释里：clip 的 lap 若漏掉被裁掉的三角形，它的耗时会被错记进**下一个**三角形的
VS 段（:144-145）；被拒绝的三角形也消费了投影+setup 时间，同样要归段（:65）。**setup 与 raster 必须
`+=` 而不是覆盖**：扇形重三角化（:152）对 n 顶点凸多边形进入 rasterOne n−2 次，`=` 只留最后一个子
三角形。`tests/unit/test_pipeline_integration.cpp:276-287` 造了被裁成 ≥5 顶点的单三角形（≥3 个子三角
形）让累加真被跑到：只把 msRaster 改 `=` 比值即跌破 0.5 红；只改 msSetup 一处**不红**——setup 份额仅
~3.5%，不足以跌破下界。这是份额使然，不是测试漏（P115 变异已真跑归档）。

**lapMs vs elapsedMs**（`src/bench/timer.h:23-34`）：lap 读一次时钟并重启在当下，相邻 lap 首尾相接，
求和 telescoping 成"最后一次 lap − 起点"⇒ 四段**划分** drawRange 的时间；`elapsedMs()` 不重启，逐段
用它得到的是累计值（片段 1 第三行）。一帧只有一个 dt：主循环在 `main.cpp:515-517` 用 `clock.lapMs()`
结算一次，节流与 FPS 打印共用它。`stage_timers_partition_the_total`
（`test_pipeline_integration.cpp:232-261`）钉住 sum(ms*) ∈ [0.5, 1.05]×msTotal，实测比值
0.9994–0.9997（三种构建各 3 次，注释 :237-239）。比值断言独有的牙齿是"四段写同一个数"（ratio≈4
而各段 >0 全绿）；删掉某段写入则红在"该段 >0"（`stage_timers_are_written`，:214-230）——两条各守一半。

**读时钟次数——注释曾经说谎的地方，以现状为准**：`stats == nullptr` 时所有 lap 都被守卫不再读，
但 `Timer total/stage` 的构造各**无条件**读一次（`timer.h:17`；`render_backend.cpp:41,52`）⇒
**每次 draw call 固定 2 次读，不是 0 次**。旧注释"一次时钟都不读"是假的（P106），现已在
`stats.h:37-38` 与 `render_backend.cpp:49-51` 更正。未裁剪三角形恰好 4 次 lap；裁剪成 n 顶点的多边形
= 2 + (n−2) 次 setup lap + 每个被接受子三角形一次 raster lap，n ≤ 10 ⇒ 至多 **18** 次（P107，
`render_backend.cpp:45-48`、`stats.h:35-36`；`docs/notes/M6-光照与休眠接口.md` §⑤ 仍写"至多 16 次读"，
与代码的 18 不符，以代码为准）。计时开销在 notes §⑤ 实测 ≈ −0.1%，淹没在 ±3% 抖动里，但**随三角形数
线性失效**：10 万三角形/帧 ⇒ 40 万次读 ≈ 10 ms 量级，高密度场景必须重测。

## 三种视图的判据：看见什么才算对

**深度视图**（`src/render/sink.cpp:22-37`）：本仓库是非 reverse-Z，`DepthTarget::clear` 默认 1.0 =
最远（`render_target.h:44`）。非线性深度让几乎所有东西挤在 1.0 附近——直接画 raw depth 就是一片白，
毫无诊断价值。所以先归一化 `t = (d − depthNear)/(depthFar − depthNear)`（app 用默认 [0,1]，
`sink.h:36-37`），再取反 `g = 1 − t`：**近 = 亮，远 = 暗**，区间外饱和（`test_sink.cpp:29-49`），
方向显式 pin 住（`test_sink.cpp:9-27`）。出口同样编码一次（`sink.cpp:34`）：d=0.25 ⇒ 字节 225。

**灰度视图**（`sink.cpp:40-50`）：先 `decodeSRGB` 回线性，用 0.2126/0.7152/0.0722 组合亮度，再编码
一次。直接在 sRGB 字节上加权平均会让亮色区域权重失真——系数只在线性空间有意义。纯红 (1,0,0) ⇒
g=0.2126 ⇒ 字节 127。sink 只改写颜色，**绝不写深度**（`test_sink.cpp:72-85`），否则切视图会改变渲染结果。

**法线视图**（`src/render/builtin_shaders.cpp:119-129`）：`debugNormalFS` 读的是 VS 里经 normalMatrix
变换到**世界空间**的 `worldNormal`（`builtin_shaders.cpp:20`），经 05 章的 attr/w 透视正确插值到达
本像素。它**不做任何"解码回世界方向"的操作**——法线从来不是 sRGB 编码量，到达时已是世界方向；
FS 只做两件事：normalize（单位向量的加权平均是弦不是弧，长度必缩），然后线性 `(N+1)*0.5`。
**这里不编码**：颜色目标出口的 `encodeSRGB`（`render_backend.cpp:117`）是单一编码点，法线视图因此
被 gamma 编码——已知 wart，是"出口只编码一次"的**正确后果**，不是 bug。线性 0.5 的字节推导
（`test_view_mode.cpp:7-16`）：1.055 × 0.5^(1/2.4) − 0.055 = 0.735357，×255 = 187.516 ⇒ lround = **188**。
不是 128（没编码）、不是 186（gamma-2.2 纯幂）、不是 132（把解码方向当编码方向）、不是 223
（双重编码，片段 2 实测）。也别把 `decode(0.5)≈0.214` 与 `encode(0.5)→188` 混谈——前者是输入侧
采样解码，后者是输出侧编码（生产出口走 4096 格 LUT，`color.cpp:8,64-69`，误差 ≤1 LSB）。
判别力夹具：非单位法线 (1/3,1/3,1/3) ⇒ 字节 230，丢 normalize 则 213（`test_view_mode.cpp:156-168`）；
零向量 ⇒ 中灰 (188,188,188)，不是黑也不是 NaN（:170-178）；挂上 rig/mat 重算逐字节相同——视图不依赖
光照状态（:180-192）。接线级证明走真实光栅化：model 绕 Y 转 30°，像素编码的必须是**旋转后**的世界
法线（:272-289）——normalMatrix 退回单位阵在这里红。

## A/B 帧时间怎么读

`--bench N` 的**现行**语义（`src/app/cmdline.cpp:192-201`）：`bench=N`、`frames=N`、`offscreen=true`
——N 就是真跑 N 帧。历史坑：D21 之前只设 bench/offscreen **不设 frames**，`--bench 60` 实际只跑 1 帧，
"我以为在测 60 帧"比没有测量更糟；修复由 `bench_flag_runs_the_requested_number_of_frames`
（`test_pipeline_integration.cpp:263-274`）钉住。`--shade unlit|gouraud|phong`（`cmdline.cpp:274-281`）
选模式，运行时 `3` 键循环（`main.cpp:425-428`）。口径有两层：`[bench]` 的 total 是 **drawRange 时间**
（四段划分它），`[offscreen]` 的平均是**整帧**时间（含 clear/HUD/sink/写回），差值即帧内非 draw 工作
（`main.cpp:334-346`）；构建配置由上一行 `buildInfoString()` 归因（`main.cpp:330`）。

但**排序 gouraud < unlit < phong 在两个构建下都成立**，机制结论可迁移，具体比值不可外推。

为什么 gouraud 比 unlit 还快——不是测量错误：unlit 是 `texturedFS`（逐像素三线性采样），gouraud 是
`lambertPerVertexFS`（光在顶点算，FS 只输出插值色，**不采样贴图**，D17，`builtin_shaders.cpp:85-90`）。
VS 列佐证机制：gouraud 的 VS（0.031）约为另两个（0.013）的 2.4 倍——`lambertVS` 在每个顶点跑完整
Blinn-Phong（Ruling 91，`builtin_shaders.cpp:74-79`）。notes §⑤ 的区间声明同样要读：这是 12–24
三角形/帧、raster 占 ~99% 的**着色主导**区间，模式比值不许外推到几何密集场景。肉眼 A/B 用 lit 球
夹具时，`kGoldenLitSlices = 15` 的奇数 `static_assert`（`src/scene/golden_scene.h:74-77`）保证没有
顶点正对眼/点光，"摊开 vs 收紧"才不退化成空转对照（密度 12/15 是实测选的，:56-64）。

计时断言必须防抖（Ruling 84，`.superpowers/sdd/2026-11-25-soft-raster-m6-lighting/progress.md:62-67`）：
一次小 draw 可能只有 0.3 ms，lap 分辨率与调度抖动会让比值毫无意义，闪红的测试教会人忽略红。
`drawUntilMeasured`（`test_pipeline_integration.cpp:45-53`）先重复 draw 到 msTotal ≥ 2.0 ms 再判。

## 能力边界：NM DEGENERATE 与小模型悬崖

法线矩阵 = transpose(inverse(model 的 3x3))（`src/math/transform.h:65-71`；先取 3x3 避开平移列对
相对阈值的污染，:62-64）。阈值是 `eps = 1e-8·maxAbs³`（`src/math/mat.h:173`），而 `upper3x3AsMat4`
保留 `m[3][3]=1`（`mat.h:114`）⇒ maxAbs 有地板 1 ⇒ 悬崖落在 s³ = 1e-8 即 **s ≈ 2.154e-3**：均匀缩到
千分之一以下的合法模型会被判奇异（实测 scale(3e-3) 可逆、scale(1e-3) 被拒，`mat.h:166-168`）。这是
**已核实的能力边界，不是 bug 故事**（Ruling 109，
`.superpowers/sdd/2026-11-25-soft-raster-m6-lighting/progress.md:779-783`）；修复留到 M7（P119，同文件 :789-790）。

边界处的可见信号有两处，都不静默：`setNormalMatrix` 奇异时退回单位阵并发 stderr
`[normal] makeNormalMatrix 失败（奇异 model），法线矩阵退回单位阵`（`src/render/pipeline.h:59-69`）；
app 把成败取反记进 `scene.normalMatrixDegenerate`（`src/app/scene.cpp:196`），HUD 第三行追加
`NM DEGENERATE`（`scene.cpp:230`）。画面继续渲染，不黑屏，但光照会错。`nm_degenerate_flag_reaches_the_hud`
（`tests/unit/test_scene.cpp:685-702`）钉住整条链：scale(0,1,1) ⇒ 置位，单位阵 ⇒ 复位。
为什么必须是逆转置：保的是与表面垂直，不是长度 1——scale(2,1,1) 下朴素变换的点积从 0 变 3/√2
（notes §②，`test_transform.cpp:159-185`）；纯旋转的 golden 区分不了两者（Ruling 89：单测证数学，
视图/golden 证接线）。
