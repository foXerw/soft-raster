# docs/guide —— 从零实现这个渲染器

这套文档的目标不是解释现有代码，而是**让你自己能一步步把它做出来**。
每章结束时，你的程序应该处在一个能跑、能看、能验的中间状态；下一章假设上一章存在。

## 怎么用这套文档

1. **按顺序读**。章节编号就是实现顺序，不是里程碑顺序。第 03 章之前不要跳到第 07 章——
   那会用到前三章建立的结构。
2. **每章的最小片段都真的编译过**。片段放在独立目录里用单文件编译即可验证：
   `cl /EHsc /std:c++20 /W4 snippet.cpp` 或 `g++ -std=c++20 -Wall -Wextra -ffp-contract=off`。
   如果你抄的片段编不过，那是文档的错，不是你的——请把它当缺陷报告。
3. **每章末尾的"你应该看到 X；如果你看到 Y，说明 Z 错了"不是装饰**。
   它是这一章的验收判据。跳过它，你会在几章之后才发现某处从一开始就错着，
   而那时候已经分不清是哪一步引入的。
4. **`file:line` 引用指向本仓库**。文档给最小片段是为了让你理解，
   引用真实代码是为了让你知道生产版本多了什么、为什么多。两边都要看。

## 每章的固定结构

```
这一章要解决什么问题（为什么上一章不够用）
最小片段（可独立编译）
指回本仓库：file:line + 生产版本多了什么、为什么多
坑（一手来自 docs/notes/，包括被推翻过的做法）
你应该看到 X；如果你看到 Y，说明 Z 错了
```

## 与 `docs/notes/` 的分工

- **`docs/notes/Mn-*.md` 是推导与坑的一手记录**：某个断言为什么曾经错、
  两个错误怎么互相抵消、哪条注释曾经说谎。它按里程碑组织，是"发生了什么"。
- **本系列是按实现顺序的重建**：它读 notes，但把内容重排成"你可以怎么走一遍"。
  同一个坑在两边都出现时，notes 给证据，这里给路径。

**06 深入：这张基准图为什么在 ±1 门禁下是绿的，却能在语义级变异下红。**

1. **绿是被构造出来的，不是运气。** 参考图由被测的那个确定函数生成（无随机、无时间项）。复跑时 M4 与参考
   **逐字节相同**；M3 只有 **2 个像素、单通道各 −1**，`maxChannelDelta = 1` ⇒ ±1 门禁按设计放过它。
   这 2 像素是参考图停在 `3f8cc2a` 之后 `src/render`+`src/scene` 又走了几十个提交带来的舍入漂移
   （章 `:176` 给了窗口命令，你复跑只会变大），这正是"弱一档门禁的诚实代价"。
2. **语义变异会红，因为它动的是几何而不是舍入。** 把 `viewport.cpp:14` 的 `1.0f -` 删掉（y 翻转消失）重编：
   M3 **4674 个像素全部差 > 1**（`maxChannelDelta = 116`），M4 4001 个（其中 3990 个 > 1，`maxΔ204`）——
   精确与 ±1 两档同时红。而**计数器一个都不变**（`covered=4239`、`depthRejected=0`）：
   覆盖/深度统计对这类变异没有判别力，只有像素比对红。
3. **诚实的边界：不是每个语义变异都红。** 把 `render_backend.cpp:95` 的 `<=` 改成 `<`（平局语义反转）重编，
   输出与基线**逐字节相同**——因为凸立方体 + 背面剔除 ⇒ `depthRejected=0`，场景里**不存在共面平局**，
   该谓词在这个错误下根本不被触发。所以"±1 绿"推不出"语义正确"：双翻转抵消（Ruling 77）只留 3 个 ±1
   舍入像素，±1 门完全放过，零容差抓到的也只是舍入噪声。**可靠判别只能是锚 1/2 的逐字段/逐字节断言。**
   ⇒ `±1 门守"重构没改变画面"，语义锚守"画面为什么对"，两者不可互替。
