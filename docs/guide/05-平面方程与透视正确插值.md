# 05 — 平面方程与透视正确插值

## 这一章要解决什么问题

第 03 章回答了"哪些像素在三角形里"，第 04 章回答了"顶点落在屏幕哪里"（clip 坐标经视口除 w、
翻 y，`src/render/viewport.cpp:7-19`，w 与 invW 被单独保留下来）。剩最后一个问题：**每个像素是什么颜色、什么 uv？**
M3 之前的答案是 flat——取第一个顶点的 varying 发给 FS（`src/render/pipeline.h:88` 的注释记着这段历史）。
这一章把它换成真插值，并且换对： naive 的"按屏幕位置线性插属性"在正对时完全正确（w 处处相等时它**就是**对的，
`tests/unit/test_interpolate.cpp:57-66` 划出这条边界），斜视角立刻错——纹理被拉向三角形中心，
本该向远处收窄的条纹变成等宽。章末你手里是一个条纹向远端正确压缩的四边形，和一句能背下来的话：
**屏幕空间里线性的是 attr/w 与 1/w，不是 attr。**

## 平面方程：每三角形解一次，每像素求值一次

仿射平面 `f(x,y) = n0*x + n1*y + c` 由三个 `(x,y,value)` 点定死。令 d1=p1−p0、d2=p2−p0、g1=v1−v0、g2=v2−v0，
则 `[d1.x d1.y; d2.x d2.y]·[n0;n1] = [g1;g2]`，2x2 克莱姆法则解出；**det 恰好就是两倍有向面积 area2**，
共线三点 det≈0、无解（`src/render/plane_eq.h:83-101`）。

为什么存"每三角形一组平面系数"而不是每像素算重心坐标：重心路线每像素要 λ0,λ1,λ2（三个边函数除以 area2），
再对每个属性 3 乘 2 加；平面路线每属性只要 2 乘 2 加（`plane_eq.h:104` 的 `sample`），2x2 求解每三角形一次、
12 个分量共用同一个 det（`src/render/triangle_setup.cpp:58-71`）。生产版一共 14 张平面：
12 个 varying 分量 + 1/w + depth（`src/render/triangle_setup.h:61-68`）。仿射还有第二个回报：前向差分——
行内 `f += n0` 即可步进（第 03 章 `coveredInc` 的同一家族），M9 的 SIMD 向量化就是这一段；
`interpolateAt` 因此 header-only、必须可内联（`src/render/interpolate.h:27-28`）。

退化是**报告**而不是求解：`!(std::fabs(det) > 1e-20f)` 置 `degenerate`，系数保持 0，调用方看标志不看值
（`plane_eq.h:94-97`）。两个细节：守卫写成 `!(fabs(det) > eps)` 而不是 `fabs(det) < eps`，因为 NaN 的任何比较
都是 false，后者会让 NaN 漏进除法，一个 NaN 像素顺着插值污染一整块（`tests/unit/test_plane_eq.cpp:40-51`
钉住；`plane_eq.h:13-14` 注释记录改 naive 形式后该测试三处断言全红）；几何层其实先按 |area2|≤1e-6 拒过一遍
（`src/render/triangle_geom.h:42`），setup 里 planeInvW 退化再拒一次（`triangle_setup.cpp:62-65`），
PlaneEq 自己的 1e-20 是直接调用者的底线。MSVC C4723 假阳性与整头 pragma 的取舍见 `plane_eq.h:9-24`。

// g++ -std=c++20 -Wall -Wextra -ffp-contract=off snippet1.cpp -o snippet1 && ./snippet1
// cl /nologo /EHsc /std:c++20 /W4 /D_CRT_SECURE_NO_WARNINGS snippet1.cpp /Fe:snippet1.exe && snippet1.exe

#include <cstdio>
#include <limits>
#if defined(_MSC_VER)
#pragma warning(push)
#pragma warning(disable : 4723)   // 同生产 plane_eq.h：C4723 是数据流假阳性，守卫已排除 0
#endif
struct Vec2 { float x, y; };
struct PlaneEq {
    float n0 = 0, n1 = 0, c = 0;
    bool degenerate = false;
    static PlaneEq fromTriangle(const Vec2& p0, float v0, const Vec2& p1, float v1,
                                const Vec2& p2, float v2) {   // 过三个 (x,y,value) 点
        PlaneEq f;
        const float d1x = p1.x - p0.x, d1y = p1.y - p0.y, d2x = p2.x - p0.x, d2y = p2.y - p0.y;
        const float g1 = v1 - v0, g2 = v2 - v0;
        const float det = d1x * d2y - d1y * d2x;               // = 两倍有向面积 area2
        if (!(std::fabs(det) > 1e-20f)) { f.degenerate = true; return f; }  // NaN 也走这条
        f.n0 = (g1 * d2y - g2 * d1y) / det;                    // 2x2 克莱姆法则
        f.n1 = (d1x * g2 - d2x * g1) / det;
        f.c = v0 - f.n0 * p0.x - f.n1 * p0.y;
        return f;
    }
    float sample(float x, float y) const { return n0 * x + n1 * y + c; }
};
int main() {
    const Vec2 p0{2, 3}, p1{9, 1}, p2{5, 8};                   // 仓库 test_plane_eq 同夹具
    const PlaneEq f = PlaneEq::fromTriangle(p0, 10.f, p1, 20.f, p2, 30.f);
    const float det = (p1.x - p0.x) * (p2.y - p0.y) - (p1.y - p0.y) * (p2.x - p0.x);
    std::printf("det(area2)=%.0f  n0=%.6f n1=%.6f c=%.6f\n", double(det), double(f.n0), double(f.n1), double(f.c));
    std::printf("vertices: %.4f %.4f %.4f\n", double(f.sample(p0.x, p0.y)), double(f.sample(p1.x, p1.y)), double(f.sample(p2.x, p2.y)));
    const float cx = (p0.x + p1.x + p2.x) / 3.f, cy = (p0.y + p1.y + p2.y) / 3.f;
    std::printf("centroid(%.4f,%.4f): %.6f  (arithmetic mean = 20)\n", double(cx), double(cy), double(f.sample(cx, cy)));
    const PlaneEq g = PlaneEq::fromTriangle({0, 0}, 1.f, {2, 2}, 2.f, {4, 4}, 3.f);   // 共线
    std::printf("collinear: degenerate=%d n0=%g n1=%g c=%g sample(1,1)=%g finite=%d\n",

## 为什么屏幕线性插 attr 是错的

先钉住"什么在什么空间里线性"。沿 3D 边 P(t)=P0+t(P1−P0)：clip=M·eye 是仿射的，所以 **attr(t) 与 w(t)
各自对 t 仿射**；但屏幕坐标 s(t)=clip.xy(t)/w(t) 是线性/线性，对 t 不仿射。把 t(s) 反解出来代回，两行代数：

```
1/w    = (Δc − s·Δw) / (w0·Δc − c0·Δw)
attr/w = (a0·Δc − c0·Δa + s·(w0·Δa − a0·Δw)) / (w0·Δc − c0·Δw)
```

两者**对 s 仿射**；而 attr=(attr/w)/(1/w) 是两个仿射之商，w 不恒定就不仿射。机制到此为止，剩下是算术。
数值落点（仓库断言值，`tests/unit/test_interpolate.cpp:68-82`）：一条边 w 从 1 到 10、u 从 0 到 1，
屏幕中点 invW=0.55、u/w=0.05 ⇒ u=**1/11≈0.0909**；屏幕线性给 **0.5**。测试同时断言 |u−0.5|>0.4——
证明这条测试有区分力，而不是"等于某个数"就算过。直觉一句：远处一个像素覆盖更多表面，属性本该在那里变化更快；
屏幕线性把它摊匀，等于把远端纹理拉向近端/中心（M3 notes §1）。

## 为什么插 attr/w、每像素再除

方案三行（`src/render/interpolate.h:17-25`）：`invW=planeInvW(x,y)`；`attr=planeAttr(x,y)/invW`；
`depth=planeDepth(x,y)` 不除。planeAttr 建在 **attr/w** 上：setup 先把每个分量乘 invW 再解平面
（`triangle_setup.cpp:66-71`）。它与"1/w 加权重心"是同一个公式：屏幕重心 λ 能 reproduces 任何仿射函数
（g=Σλi·g(vi)），分别作用于 attr/w 与 1/w 得 planeAttr=Σλi·attr_i/w_i、planeInvW=Σλi/w_i，
相除即透视正确加权平均。但"每像素除"只花**一次倒数、12 个分量共享**（`interpolate.h:43-50`），
不必每像素归一化 λ——这就是选平面系数的代价账。

**clip 空间里线性的是 attr 与 w 各自，不是 attr/w**——这是与第 04 章的边界：裁剪阶段对未除的 attr 与 w
用同一个 t 插，除法留到投影之后（`src/render/vertex.h:56-67`）。写反就是复审 C2（commit `cd7c6b0`）：
A(w=1,u=0)、B(w=2,u=3)、t=0.5 处正确值 1.5/1.5=**1.0**，插 attr/w 得 **0.75**，25% 误差，症状是贴近或穿进
模型时颜色与 UV 在裁剪边界扭曲；旧精确夹具所有 w=1，而 w 恒定时 attr/w 就是线性的，结构上抓不到
（`tests/unit/test_clipping.cpp:123-146` 是后补的守门测试）。**M2 notes §2 仍是 C2 之前的旧说法，以 vertex.h 为准。**

两个推论，各有测试：
- **屏幕线性插的是 1/w，不是 w。** w 本身不屏幕仿射：片段 2 实测中点 w=1.333333，屏幕线性会给 1.5。
  1/w 不需要校正，因为它自己就是仿射的（上面引理取 attr≡1）。
- **depth 不需要校正**：depth=ndcZ*0.5+0.5，ndcZ=z_clip/w，z_clip 对 3D 仿射、w=−z_eye
  （`src/math/transform.h:28`），同一条引理 ⇒ ndcZ 屏幕仿射（`test_interpolate.cpp:84-93`，中点 0.4 是断言值）。

## 最小片段 2：一个四边形，两种插值

四边形不是手摆的梯形：3D 矩形绕 Y 转 30°、相机距 1.5 真投影，近边 w=1、远边 w=2。光栅部分复用第 03 章
边函数，sign 吸收绕向、不做剔除——插值正确性与绕向无关（`test_interpolate.cpp:24-30` 同理由）；
正面判据始终是 area2<0 加语义 `dot(法线, eye−顶点)`，别信 CW/CCW 这个词（第 03 章）。

```cpp
// snippet2.cpp — 同一斜视角四边形两种插值：屏幕线性 attr（错）vs attr/w 再除（对）→ 两张 BMP
// 四边形是真实 3D 矩形绕 Y 转 30°、相机距 1.5 的透视投影 ⇒ 近边 w=1、远边 w=2（2:1）。
// g++ -std=c++20 -Wall -Wextra -ffp-contract=off snippet2.cpp -o snippet2 && ./snippet2
// cl /nologo /EHsc /std:c++20 /W4 /D_CRT_SECURE_NO_WARNINGS snippet2.cpp /Fe:snippet2.exe && snippet2.exe
#include <algorithm>
#include <cmath>
#include <cstdint>
#include <cstdio>
#include <vector>
#if defined(_MSC_VER)
#pragma warning(push)
#pragma warning(disable : 4723)   // 同生产 plane_eq.h
#endif
struct Vec2 { float x, y; };
static float cross(Vec2 a, Vec2 b) { return a.x * b.y - a.y * b.x; }
struct Edge {                                   // 第 03 章的边函数，sign 吸收绕向
    Vec2 n; float c;
    static Edge from(Vec2 a, Vec2 b, float s) {
        Vec2 e{b.x - a.x, b.y - a.y};
        Edge f{{-e.y * s, e.x * s}, 0.f};
        f.c = -(f.n.x * a.x + f.n.y * a.y);
        return f;
    }
    float eval(Vec2 p) const { return n.x * p.x + n.y * p.y + c; }
    bool tl() const { return n.x > 0.f || (n.x == 0.f && n.y > 0.f); }
    bool covers(Vec2 p) const { float v = eval(p); return v > 0.f || (v == 0.f && tl()); }
};
struct PlaneEq {                                // 与 snippet1 相同
    float n0 = 0, n1 = 0, c = 0;
    bool degenerate = false;
    static PlaneEq fromTriangle(const Vec2& p0, float v0, const Vec2& p1, float v1, const Vec2& p2, float v2) {
        PlaneEq f;
        const float d1x = p1.x - p0.x, d1y = p1.y - p0.y, d2x = p2.x - p0.x, d2y = p2.y - p0.y;
        const float g1 = v1 - v0, g2 = v2 - v0, det = d1x * d2y - d1y * d2x;
        if (!(std::fabs(det) > 1e-20f)) { f.degenerate = true; return f; }
        f.n0 = (g1 * d2y - g2 * d1y) / det; f.n1 = (d1x * g2 - d2x * g1) / det;
        f.c = v0 - f.n0 * p0.x - f.n1 * p0.y;
        return f;
    }
    float sample(float x, float y) const { return n0 * x + n1 * y + c; }
};
struct Tri { Edge e[3]; int x0 = 0, y0 = 0, x1 = -1, y1 = -1; PlaneEq lin, uw, iw; };
static bool build(const Vec2 v[3], const float u[3], const float w[3], int W, int H, Tri& t) {
    const float a2 = cross({v[1].x - v[0].x, v[1].y - v[0].y}, {v[2].x - v[0].x, v[2].y - v[0].y});
    if (!(std::fabs(a2) > 1e-6f)) return false;
    const float s = a2 > 0.f ? 1.f : -1.f;
    for (int i = 0; i < 3; ++i) t.e[i] = Edge::from(v[i], v[(i + 1) % 3], s);
    t.x0 = std::max(0, (int)std::floor(std::min({v[0].x, v[1].x, v[2].x}) - .5f));
    t.x1 = std::min(W - 1, (int)std::ceil(std::max({v[0].x, v[1].x, v[2].x}) - .5f));
    t.y0 = std::max(0, (int)std::floor(std::min({v[0].y, v[1].y, v[2].y}) - .5f));
    t.y1 = std::min(H - 1, (int)std::ceil(std::max({v[0].y, v[1].y, v[2].y}) - .5f));
    float iw[3], uw[3];
    for (int i = 0; i < 3; ++i) { iw[i] = 1.f / w[i]; uw[i] = u[i] * iw[i]; }
    t.lin = PlaneEq::fromTriangle(v[0], u[0], v[1], u[1], v[2], u[2]);       // 错：裸 attr
    t.uw = PlaneEq::fromTriangle(v[0], uw[0], v[1], uw[1], v[2], uw[2]);     // 对：attr/w
    t.iw = PlaneEq::fromTriangle(v[0], iw[0], v[1], iw[1], v[2], iw[2]);     // 1/w
    return t.x0 <= t.x1 && t.y0 <= t.y1 && !t.lin.degenerate && !t.uw.degenerate && !t.iw.degenerate;
}
static void bmp(const char* path, const std::vector<uint32_t>& px, int W, int H) {
    const int rb = W * 3, pad = (4 - rb % 4) % 4; const uint32_t ds = (uint32_t)((rb + pad) * H);
    uint8_t h[54] = {};
    auto p32 = [&](int o, uint32_t v) { for (int i = 0; i < 4; ++i) h[o + i] = (uint8_t)(v >> (8 * i)); };
    h[0] = 'B'; h[1] = 'M'; p32(2, 54 + ds); p32(10, 54); p32(14, 40);
    p32(18, (uint32_t)W); p32(22, (uint32_t)H); h[26] = 1; h[28] = 24; p32(34, ds); p32(38, 2835); p32(42, 2835);
    FILE* fp = std::fopen(path, "wb"); std::fwrite(h, 1, 54, fp);
    std::vector<uint8_t> row((size_t)(rb + pad), 0);
    for (int y = H - 1; y >= 0; --y) {          // 文件 bottom-up，内存 top-down
        for (int x = 0; x < W; ++x) {
            const uint32_t c = px[(size_t)y * W + x];
            row[(size_t)x * 3] = (uint8_t)c; row[(size_t)x * 3 + 1] = (uint8_t)(c >> 8); row[(size_t)x * 3 + 2] = (uint8_t)(c >> 16);
        }
        std::fwrite(row.data(), 1, row.size(), fp);
    }
    std::fclose(fp);
}
int main() {
    const int W = 256, H = 256;
    const float theta = 30.f * 3.14159265f / 180.f, dist = 1.5f, fpx = 128.f;
    const float ct = std::cos(theta), st = std::sin(theta);
    const float lx[4] = {-1.f, 1.f, 1.f, -1.f}, ly[4] = {-0.75f, -0.75f, 0.75f, 0.75f};
    Vec2 q[4]; float u[4], w[4];
    for (int i = 0; i < 4; ++i) {               // z_eye = -1.5 - sin30°*x ⇒ w = 1.5 + 0.5x
        w[i] = dist + st * lx[i];
        q[i] = {128.f + fpx * ct * lx[i] / w[i], 128.f - fpx * ly[i] / w[i]};
        u[i] = (lx[i] + 1.f) * 0.5f;            // 纹理坐标：左缘 0，右缘 1
    }
    const Vec2 vA[3] = {q[0], q[1], q[2]}, vB[3] = {q[0], q[2], q[3]};
    const float uA[3] = {u[0], u[1], u[2]}, uB[3] = {u[0], u[2], u[3]};
    const float wA[3] = {w[0], w[1], w[2]}, wB[3] = {w[0], w[2], w[3]};
    Tri ta{}, tb{};
    if (!build(vA, uA, wA, W, H, ta) || !build(vB, uB, wB, W, H, tb)) { std::printf("build failed\n"); return 1; }
    std::printf("quad: near w=%.3f far w=%.3f (2:1), corners x=%.3f..%.3f\n", double(w[0]), double(w[1]), double(q[0].x), double(q[1].x));
    std::vector<uint32_t> wrong((size_t)W * H, 0xFF101010u), right((size_t)W * H, 0xFF101010u);
    float maxDev = 0, maxVertErr = 0; int mx = 0, my = 0, cov = 0; int64_t clamped = 0;
    for (int tri = 0; tri < 2; ++tri) {
        const Tri& t = tri ? tb : ta;
        const Vec2* vv = tri ? vB : vA; const float* uu = tri ? uB : uA;
        for (int k = 0; k < 3; ++k) {           // 正确插值必须还原顶点值
            const float uc = t.uw.sample(vv[k].x, vv[k].y) / t.iw.sample(vv[k].x, vv[k].y);
            maxVertErr = std::max(maxVertErr, std::fabs(uc - uu[k]));
        }
        for (int y = t.y0; y <= t.y1; ++y) for (int x = t.x0; x <= t.x1; ++x) {
            const Vec2 p{x + .5f, y + .5f};
            if (!(t.e[0].covers(p) && t.e[1].covers(p) && t.e[2].covers(p))) continue;
            ++cov;
            const float uL = t.lin.sample(p.x, p.y);
            float iw = t.iw.sample(p.x, p.y);
            if (!(std::fabs(iw) > 1e-8f)) { ++clamped; iw = (iw < 0.f) ? -1e-8f : 1e-8f; }   // 生产同款夹住
            const float uC = t.uw.sample(p.x, p.y) * (1.f / iw);
            const float dev = std::fabs(uL - uC);
            if (dev > maxDev) { maxDev = dev; mx = x; my = y; }
            wrong[(size_t)y * W + x] = (int(uL * 8.f) & 1) ? 0xFFE08020u : 0xFF203060u;
            right[(size_t)y * W + x] = (int(uC * 8.f) & 1) ? 0xFFE08020u : 0xFF203060u;
        }
    }
    std::printf("covered=%d clamped=%lld maxVertexErr=%.2e\n", cov, (long long)clamped, double(maxVertErr));
    std::printf("max |u_linear - u_correct| = %.6f at (%d,%d) = %.2f texels of a 256-wide texture\n", double(maxDev), mx, my, double(maxDev * 256.f));
    const float xm = (q[0].x + q[1].x) * 0.5f, ym = 128.f;
    const float iwM = ta.iw.sample(xm, ym), uwM = ta.uw.sample(xm, ym);
    std::printf("screen midpoint x=%.3f: u_linear=%.6f | invW=%.6f u/w=%.6f => u_correct=%.6f (1/3)\n",
                double(xm), double(ta.lin.sample(xm, ym)), double(iwM), double(uwM), double(uwM / iwM));
    std::printf("w at midpoint: actual=%.6f  screen-linear-w-would-be=%.6f (w itself is NOT affine)\n", double(1.f / iwM), double((w[0] + w[1]) * 0.5f));
    const float xWrong = (0.5f - ta.lin.c - ta.lin.n1 * ym) / ta.lin.n0;      // u=0.5 纹理中线落点
    const float dn0 = ta.uw.n0 - 0.5f * ta.iw.n0, dn1 = ta.uw.n1 - 0.5f * ta.iw.n1, dc = ta.uw.c - 0.5f * ta.iw.c;
    const float xRight = -(dc + dn1 * ym) / dn0;
    std::printf("u=0.5 stripe: wrong x=%.3f right x=%.3f shift=%.3f px\n", double(xWrong), double(xRight), double(xRight - xWrong));
    bmp("wrong.bmp", wrong, W, H); bmp("right.bmp", right, W, H);
    std::printf("bmp: wrong.bmp right.bmp (8 stripes in u)\n");
}
#if defined(_MSC_VER)
#pragma warning(pop)
#endif
```

## 指回本仓库：生产版本多了什么

### Varyings：12 个 float、无填充，断言是接口的一部分

布局写死四槽：color 分量 0..3、worldNormal 4..6、uv 7..8、worldPos 9..11（`src/render/vertex.h:15-20`），
`kVaryingFloatCount = 12` 加 `static_assert(sizeof(Varyings) == 12*sizeof(float))`（`vertex.h:22-24`）。
为什么钉：`interpolateAt` 把 `&out.v` reinterpret 成 `float*` 按分量下标写（`interpolate.h:47-50`），
setup 用 `varyingFloats` 按分量读（`vertex.h:35`），M9 的 SIMD 一次读 4 个分量（`vertex.h:13-14`）。
**删掉断言会怎样**：插一个 bool、换一个带对齐的成员，sizeof≠48，第 f 张平面就对应错槽位——
颜色与 uv 串味、甚至越界读，而且编译照过、运行照跑，症状只是"画面有点怪"。所以它有两条测试钉：
`tests/unit/test_viewport.cpp:76-94`（sizeof + 逐分量读回 + 字段名）、`tests/unit/test_lit_shaders.cpp:583-584`
（D6：Gouraud 的光照结果写进**已有** color 槽，不新增 varying）。固定四槽而不是通用 attribute 表也是决定：
通用表意味着每帧查布局描述符，本项目的目标是看清每个阶段（`vertex.h:9-14`）。断言自创建管线类型的
`c678b9d` 就在（`git log -S` 实测）；M6 加光照没加槽，修复波结束时仍 12 float
（`.superpowers/sdd/2026-11-25-soft-raster-m6-lighting/progress.md:714`）。

### setup 与 interpolateAt 比片段多的

- **非有限检查连 depth/invW/w 一起查**（`triangle_setup.cpp:26-31`）：只查 pos 的话 NaN 从深度或 1/w 溜进插值。
  拒绝顺序非有限→退化→朝向→离屏是接口（M2 notes §5）。
- **invW 趋零保号夹到 1e-8 并计数**（`interpolate.h:33-43`），计数上 HUD，"三角形几乎平行视线"是可见的。
  测试 `inv_w_near_zero_is_clamped_and_counted`（`test_interpolate.cpp:95-112`）第一版采样点 (9.9,0.1) 处
  invW 还有 0.01，根本没走到夹住分支——计数为 0 才暴露（M3 notes §2）。
- **uv 屏幕导数**：uv=A/I 的商法则，在重心取一次（`triangle_setup.cpp:73-84`），M4 的 mip 选择消费它。
  入口收 `gradU/gradV` 两个 Vec2 而不是四个 float：旧名 uvDerivX/Y 与参数顺序差一次转置，填错只糊不崩
  （`src/render/pipeline.h:89-95`）。
- 调用点每像素一次 `interpolateAt`（`src/render/render_backend.cpp:83-87`）；颜色出口 encodeSRGB 单点（:117）。

### 谁受透视处理，shader 的契约是什么

| 量 | 屏幕仿射？ | 处理 |
|---|---|---|
| 12 个 varying 分量（color/normal/uv/worldPos） | 否 | 建 attr/w 平面，每像素乘 w（`triangle_setup.cpp:66-71`） |
| depth = ndcZ*0.5+0.5 | 是 | 直接平面，不除（`triangle_setup.h:64-67`） |
| 1/w | 是 | 直接平面 planeInvW |
| w 与 attr 本身 | 否 | 不在屏幕空间直接插 |
| 屏幕位置 | — | 逐顶点视口算出（`viewport.cpp:12-14`），不插值 |

顶点色也是属性，没有豁免。两条契约：插值法线会缩（单位向量的加权平均是弦不是弧），FS 必须再 normalize
（`src/render/builtin_shaders.cpp:111-114`；`src/render/shading.h:6-7` 约定被调方不替调用方归一化）；
worldPos 曾错赋成物体空间而当时没有 FS 读它，错了也没人发现（`builtin_shaders.cpp:22-24` 注释记录）——休眠字段不是正确性证据。
调试视图的分界（D23，`src/render/sink.h:18-25`）：能逐像素判定的（法线）走普通 FS，需要整张缓冲的（深度/灰度）
走帧末 sink；两种机制并存是设计，别去"统一"。

### 数值

全路径 float；GCC 侧 `-ffp-contract=off`（`CMakeLists.txt:59-60`）：默认 fast 会把插值融合成 FMA 而 MSVC 不融合。
容差（仓库断言值）：透视中点与 invW 1e-5（`test_interpolate.cpp:79-81`）、顶点还原 1e-3（:50）、depth 1e-4（:52、:92）、
plane_eq 顶点 1e-4（`test_plane_eq.cpp:16-18`）；golden ±1/255/通道、只在 MSVC 判定（M3 notes §6）。
本章两个片段与 sRGB 探针在两条工具链打印一致（实测）。sRGB 探针（链 `src/render/color.cpp`）：
0.5 线性 → 字节 **188**；纯 R/G/B 的 sRGB 字节平均 = **85**，而线性平均 1/3 的 sRGB 字节 = **156**——
平均必须在线性空间做，测试解码回线性再比、容差 0.09（`tests/unit/test_vertex_color.cpp:44-63`，M3 notes §4）。

## 你应该看到 X；如果你看到 Y，说明 Z 错了

你应该看到：片段 1 `det=41`、重心 `20.000002`、共线与 NaN 都 `degenerate=1` 且系数有限；
片段 2 `covered=23932`、最大偏差 `0.171573`（43.92 纹素）、中点 `u_correct=0.333333`、中线错位 `27.713 px`；
`right.bmp` 条纹向远端压缩、`wrong.bmp` 等宽。

如果你看到：
- **条纹等宽 / 中点 u=0.5**：平面建在裸 attr 上，或忘了除 invW——回到引理，检查 setup 乘 invW 的那一步。
- **2:1 四边形中点 u≈0.0909**：你把 1/11 夹具的期望抄过来了，1/11 属于 w 比 1:10，不是 1:2。
- **NaN 色块**：invW 夹住缺失，或退化守卫写成 naive 形式（片段 1 最后两行就是它的样子）。
- **covered=0**：绕向 sign 没吸收（第 03 章），与插值无关；插值不改覆盖。
- **对角线缝或双写**：fill rule（第 03 章），同样不是插值的锅。
- **颜色与 uv 串味**：Varyings 有了填充或槽序被改——static_assert 本该先红，检查你是不是删了它。
